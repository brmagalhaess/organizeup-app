# ADR-0003 — Interface

Status: aceito (2026-10-29)

- **Mobile-first**. O painel usa moldura de aplicativo (`components/shell/app-shell.tsx`): menu lateral
  fixo a partir de `lg` e área de trabalho em largura total, sem `max-width`; no celular, barra inferior
  com Painel, Lançamentos, Lançar e Mais. Módulos futuros entram no menu como "Em construção".
- **Revelação progressiva**: formulários abrem em painel lateral (`Sheet`), não ocupam a tela. Lançar
  funciona de qualquer tela pelo provedor `entry-context.tsx`. Primeiro uso guiado por "Primeiros passos".
- **Rotas**: `app/app/(inicio)` para criar ou escolher família; `app/app/(painel)` para o sistema.
- **Gráficos**: tokens `income` e `expense` validados para daltonismo nos dois temas; um eixo só, legenda,
  tooltip e tabela para leitores de tela. Texto nunca usa a cor da série. Situação sempre com ícone e rótulo.
- **PWA instalável** na Fase 2 (manifest + service worker do shell).
- **Tokens de design** em `apps/web/src/app/globals.css` (`@theme`); componentes só usam tokens.
  Tema claro/escuro por `prefers-color-scheme`.
- **Kit de componentes** em `apps/web/src/components/ui.tsx`: `Button`, `Field` (liga rótulo, dica e
  erro por `htmlFor`/`aria-describedby`), `Input`, `Select`, `Card`, `FormMessage`, `PageHeader`, `StatTile`, `Badge`, `EmptyState`, `IconButton`,
  `Sheet`, `ConfirmSheet`. Classes usadas também no servidor ficam em `components/styles.ts`, sem
  `"use client"`. Próximos: input monetário com máscara, date picker pt-BR, confirmação de sugestão.
- **Formatação** sempre pelos helpers (`formatBRL`, `Intl` pt-BR); nada de formatação manual.
- **Acessibilidade**: alvo WCAG 2.1 AA; o e2e roda axe nas telas principais e falha com violações.
- **Spec antes de código**: toda issue de tela traz campos, estados (vazio, erro, carregando,
  primeiro uso) e textos.
